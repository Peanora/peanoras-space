# 站点账号、友链与留言

更新：2026-11-20。

从首页封面点「账号登录」。首次用邮箱验证码验证身份，登录后填写用户名和密码。后续可用用户名密码登录，也可用邮箱验证码恢复访问后更改密码。两种方式使用同一个 Supabase 用户 ID，原有私人待办随账号保留。用户名为 3–24 位字母、数字或下划线，大小写等同，设置后固定。密码最短为 6 个字符。

「社交 → 友链」和「社交 → 留言」允许任何人阅读已公开条目。登录者可以提交申请或留言，在「我的提交」看状态或撤回。公开列表只返回填写的展示名称、正文、链接、日期和条目标识，不包含账户邮箱或用户 ID。默认没有示例友链或留言。

## 上线顺序

1. 在现有 `peanoras-space` Supabase 项目中依次执行 [社区与账号迁移](../supabase/migrations/202611200001_site_accounts_and_community.sql) 和 [站内审核迁移](../supabase/migrations/202611200002_site_owner_moderation.sql)。已有 TODO 线上表只需沿用。
2. 在同一项目确认用户指定的邮箱对应唯一一个已验证账号。使用数据库管理权限，将其用户 ID 保存到 `site_private.owner.user_id`。同一项目只允许一位站主，重复指定同一账号可沿用记录。网站账号和浏览器无法修改此绑定。
3. 使用登录了同一 Supabase 项目的 CLI，从仓库根目录部署函数。CLI 可通过 `npx supabase` 启动，无需把访问令牌写入仓库。

   ```powershell
   npx supabase functions deploy username-login --remote=oybzmebyslabrjgkfuml --no-verify-jwt --use-api
   ```

   登录请求还没有用户令牌，函数因此接收未登录请求，再由 Supabase Auth 校验密码。函数仅接受 `https://peanora.cn` 及本地 5173 的浏览器来源。映射和限流仅服务器角色可查询。函数读取 Supabase 提供的服务器环境变量；前端继续沿用两个已有的公开构建变量。参考 [函数验证配置](https://supabase.com/docs/guides/functions/function-configuration) 和 [函数环境变量](https://supabase.com/docs/guides/functions/secrets)。
4. 确认公开列表可读取、匿名请求不能审核、登录函数可接收来自站点的请求后，沿用现有 GitHub Pages 工作流发布前端。
5. 用已登录用户设置用户名和密码、退出、用新凭据登录，确认原待办仍存在。用站主账号查看审核入口，另一个已验证账号提交后复查待审核与公开的状态。已登录的站主可刷新页面重新读取权限。

## 审核公开内容

用站主账号登录网站，在首页账号面板打开「友链审核」或「留言审核」，也可以直接进入对应页面。待审核内容可通过或拒绝。已公开内容可撤下，未通过内容可恢复公开。作者自己撤回的条目会从审核列表移除。站主在浏览器里只看到展示名称、正文、公开网址和提交状态。

如果账号面板显示「密码设置暂不可用」，检查保存用户名的账号迁移是否已运行。能设置密码但无法用用户名登录时，检查 `username-login` 是否已部署到与网站一致的 Supabase 项目。

## 编辑 Little Things

站主登录后，在账号面板选「管理小角落」，在 Little Things 页展开「管理纸条」。可添加、修改纸条，或选择「删除」并确认。「保存到网站」后内容即可公开展示。设为彩蛋的纸条沿用小角落的随机换句规则。

上线前应用 [纸条迁移](../supabase/migrations/202611200003_little_notes.sql)。现有 JSON 纸条作为初始内容，数据库按 ID 记录站主在线保存的版本；新增纸条也存在同一处。修改保留纸条 ID 和访客收藏，数据库用版本号拒绝过时覆盖。普通账号和匿名访客可以读取纸条。开发编辑器预览仍使用当前草稿。

[删除迁移](../supabase/migrations/202611200004_delete_little_notes.sql) 为被删除的纸条记录 ID，并阻止后续重新展示原文。删除的纸条从详情、首页、侧栏和访客收藏显示中移除。

## 验证方式

- `npm test` 检查账号方法、旧待办、公开数据接口和用户名函数的处理逻辑。`npm run build` 生成 GitHub Pages 的独立入口。
- `node scripts/verify-community-rls.mjs` 在本地 PostgreSQL 引擎执行实际迁移并测试匿名、两账号和服务角色。安装可选运行库的办法见 [TODO 本地验证记录](TODO_VERIFICATION.md)。
- `scripts/verify-todo-browser.js` 使用本地模拟 HTTP 响应验证首页和社区表单，以及共享同一账号的待办。通过本地测试不代表已在真实 Supabase 项目部署或验证。

2026-11-20 本地结果：73 项单元及构建测试通过。实际迁移在本地 PostgreSQL 引擎验证了 12 组账号与社区权限，原 TODO 另有 16 组权限检查通过。Edge 浏览器使用测试接口跑通了首页弹窗、邮箱验证码、设置密码和用户名重登，以及留言通过、友链拒绝、恢复公开和撤下。真实账号的密码和审核流程仍需在线验收。
