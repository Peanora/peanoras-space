# 本机音频预览

侧栏音乐播放器支持原生音频与官方平台播放器。原生音频提供播放、暂停、进度、音量和手动切歌；未接入音频的曲目仍使用网易云或 QQ 音乐官方控件。首次访问不会自动播放。

本机音频仅在 `npm run dev` 中读取，保存在仓库根目录 `.local-audio/`，不放进 `public/`。该目录被 Git 忽略，Vite 生产构建不复制它，也不在生产包中读取本机目录。原来的 14 首歌曲、专辑、封面、官方链接仍由 `src/data/content.json` 提供，不复制一份歌曲目录。

映射文件为 `.local-audio/catalog.json`，以原歌曲稳定 ID 对应音频地址：

```json
{
  "tracks": {
    "content.json 中的歌曲 ID": {
      "src": "/.local-audio/经过 URL 编码的文件名.mp3"
    }
  }
}
```

这里只接入普通浏览器音频格式，并实际检查解码结果。网易云 NCM 不是浏览器直接支持的音频文件，不能仅修改后缀接入。文件存在或播放器加载完成不等于播放成功；界面以真实媒体事件更新状态，失败时保留官方收听入口。

站内换页、收起歌单或手机音乐面板会保留同一个播放器；停止会卸载当前音源并保留所选歌曲。播放结束默认停止，不自动连播。

若后续要随网站公开分发音频，需要单独确定可公开分发的文件与范围，再修改正式资源配置；不要直接将本机预览目录移进公共上传目录。

2026-11-10 域名核查：`https://peanora.cn/` 当前音乐卡为“加载官方播放器”，没有原生音源；正式构建中的 `DEV` 分支不会请求本机清单。本机清单对应两专 14 个可播放文件，合计 300,981,477 字节（约 287 MiB）。如果要让域名也使用同款原生控件直接播放，需要单独接入允许公开的音源；本轮未把这些文件复制到公开目录或提交到 Git。

## 同日补齐《一抹憨色》

用户后续提供普通 FLAC 目录，十首曲名、专辑、曲序与既有歌曲完全对应。原始暂存副本按歌曲 ID 命名，SHA256 与下载原件相同；原 NCM 未处理。二专四首清单和文件保持不变。

浏览器最初报 `DEMUXER_ERROR_COULD_NOT_OPEN`，ffprobe 同时报告附带封面缺少 MIME 元数据。移除附带封面和元数据后已可解码，因此另生成兼容封装，不覆盖原件或原始副本：

```powershell
ffmpeg -i .local-audio/<ID>.flac -map 0:a:0 -c:a copy -map_metadata -1 -vn .local-audio/browser/<ID>.flac
```

未使用均衡、压缩、增益或响度处理，未重编码。以 `ffmpeg -map 0:a:0 -c:a copy -f hash -hash sha256 -` 对比，10/10 编码音频包 SHA256 和时长完全相同；兼容版只有 FLAC 音频流，清单指向 `/.local-audio/browser/<ID>.flac`。
