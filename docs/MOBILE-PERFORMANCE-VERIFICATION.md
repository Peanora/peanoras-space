# 手机翻页与资源优化 · 2026-10-15

## 用户反馈与修复

- 移除首页“暂停动态”按钮，持续装饰与签名照常运行；保留系统减少动态、后台标签页自动暂停。
- 旧触摸代码只要当前屏发生纵向溢出就完全忽略滑动，而且忽略所有按钮/链接区域。现改为记录手势开始时的阅读边界：内部正常阅读，已到边界的下一次滑动才切主题。大图和链接可滑动，短按仍可进入，识别翻页后阻止误点击；双指/取消手势、横向手势和壁纸/底部工具独立处理。
- 三个书签原先直接加载整张 1920px 图，共 516,134 字节；现在使用 240px 缩略图，共 17,132 字节，约减少 96.7%。
- 插画提供 640/1080/1920px 响应式文件；浅背景最多 1080px。390px 宽、当前测试浏览器像素密度下，默认背景使用 640px 文件（30,366 字节，原文件 204,846 字节）。真实高像素密度手机会自动选择更大的副本，不能承诺所有设备固定加载 640px。
- 图片下载失败时回退缩略图并仅重试一次；没有无限请求。不能绕过 GitHub Pages 本身不可达或运营商网络问题。
- 保留字体外观与许可。Kalam/Nunito 英文网页字体从 737,828 字节降为 88,040 字节；中文仍使用原有文楷小字体包与完整包回退。

## 已验证

- `npm test`：11 项通过。包含滚轮惯性、触摸边界、先阅读后翻页、点按/横向/反向/首尾边界，以及实际 composable 事件接线的双指取消、误点击拦截、工具隔离和卸载清理。
- `VITE_BASE_PATH=/peanoras-space/` 下生产构建通过。
- 本地相同 base 的生产预览：390×844 首页、World、Music；360×640 矮屏 Music/Little，四屏目录切换可用。没有页面水平溢出，底部目录在视口内。
- 矮屏 Music 实际内容高度 595px、阅读区域 458px，确认仍可内部阅读；修复后的边界翻页由上述事件逻辑测试覆盖。
- 实际浏览器 DOM 确认首页不再有开关；背景、头像、书签、主题插画均成功加载。390px 使用 640px 背景/前景与 240px 书签；1280×720 使用 1080px 背景。
- 本地 Music 入口、详情刷新、返回首页通过；浏览器捕获的 warning/error 记录为空。
- 1280×720 下，键盘焦点在底部工具时 PageDown 会先阅读当前屏溢出的 9px，再按一次进入 My World，标题获得焦点。修正了焦点在固定工具栏时原生滚动无法读取内部内容的问题，并加入事件测试。

## 验证限制

- 浏览器尺寸模拟不是实机：未在真实 iPhone/Android、不同手机浏览器或国内移动网络验证触摸事件、手势阻止与弱网恢复。
- 当前自动化浏览器未提供触摸注入和网络故障模拟，因此不把逻辑测试称为手机实机滑动或断网重试验收。
- OS 减少动态、后台暂停保留实现，本轮未实际切换系统偏好；没有做屏幕阅读器测试。
- 资源字节变化可重现，不等同于大陆各网络的加载时间保证。
