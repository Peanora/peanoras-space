# 本地内容工作台

## 使用

1. 在项目目录运行 `npm run dev`。保留运行窗口。
2. 打开终端显示的本地地址，在后面加 `/__editor`。默认是 `http://127.0.0.1:5173/__editor`；端口被占用时以终端实际地址为准。
   工作台优先用于电脑宽窗口；若应用内浏览器侧栏太窄，请把地址复制到独立浏览器窗口打开。
3. 左侧选择首页、My World、Music & Memories 或 Little Things，再选择模块。中间是正式页面使用的组件，可以直接点击文字输入。右侧修改列表、链接地址、图片及布局。切页面保留草稿。
4. 在中间预览里选中文字，点击上方 **B / I / 列表 / 编号 / 加链接**。Enter 换行；链接需先在工具栏填写地址。右侧文本同样可编辑，Ctrl/Cmd+B、I 可调整格式。粘贴按纯文本处理，避免带入外部样式。
5. 点击“保存到项目”，或 Ctrl/Cmd+S。一次保存四页草稿；提示保存成功后，刷新普通页面也能看到内容。保存不会推送或发布。

左侧拖动模块可排序，也提供上下移动按钮；右侧可复制、隐藏、删除。误删用撤销。隐藏内容在带编辑标记的预览里半透明显示，普通页面完全隐藏。页内导航文字留空时不会添加导航项。

项目、学习方向、社交链接与经历都有添加/删除条目操作；展开条目后编辑。添加模块后直接点击标题、正文开始输入。尚未提供的真实项目/经历不自动编造。

桌面预览使用中间区域的可用宽度；手机预览容器固定为 390px，窄工作区可以横向滚动查看。响应式断点与正式网站一致，不是截图。双列、左右图文在窄屏自动单列，模块全宽。预览中的导航链接不会离开编辑页；需要正常浏览时点“打开网页”。取消“显示编辑标记”可查看干净预览。

## 目前范围

已开放四页：

- **首页**：封面大标题、欢迎语、轮播签名、头像、首页社交链接，以及三屏主题标题/介绍/入口文字/书签/插画。首页固定四屏和路由，不能删除、复制或打乱顺序；点击左侧模块切到对应屏。正式网页继续播放标题与打字机动画；编辑时静态展示第一句签名，右侧可增加、删除、排序全部签名。
- **My World**：页面标题、介绍、兴趣、学习、社交、项目、经历；保留已提供内容。
- **Music & Memories**：歌曲、官方平台链接与网易云 ID、封面、感想；回忆的日期/地点/段落/照片/纪念内容；相册照片/说明/形状/裁剪位置。网易云官方链接填写后自动识别 ID，其他平台链接保留为外链。照片新增、替换、删除、排序；相册可选择交错/等宽双列/单列。仍使用原有官方播放器和图片灯箱。
- **Little Things**：纸条文字/来源/稀有属性、收藏区说明、按钮文字和页边小记。纸条可增加、删除、排序，已有条目 ID 保持稳定。纸条内容属于网站；“我的收藏”属于每个访客自己的浏览器。工作台预览的收藏仅为临时演示，不读取或修改正式浏览的收藏记录。每页使用一个纸条与收藏模块，在模块内部管理所有条目。

三个详情页还可添加标题正文、图片说明、图文混排、链接、分隔等模块。日期、链接、签名、动画标题及播放器信息使用纯文本；正文、感想、回忆、图片说明等支持富文本。纯文本字段点格式按钮会提示，避免出现预览加粗但保存后丢失的假效果。

图片支持 PNG/JPEG/WebP/GIF。上传前非 GIF 在浏览器中缩小到最长边不超过 1920px，并转换为 WebP；GIF 保留动画。输入文件最大 12 MB。裁剪是响应式显示设置，保留资源文件本身；可调比例、填满/完整、水平/垂直位置与显示宽度。请填写替代文字。替换、清空图片或删除模块只移除引用，不删除资源文件，确保撤销和旧备份仍可找回图片。

不是自由画布，不支持任意像素定位、复杂嵌套、协作或账号系统。富文本使用原生 contenteditable 和浏览器格式命令；后者是已弃用的兼容接口，当前在 Chromium 验证，其他浏览器需要另测。内容经 DOMPurify 白名单处理，不允许脚本、任意样式或 HTML 嵌入。正式网页的外部播放器与既有业务不受影响。

## 保存和恢复

- 主内容：`src/data/content.json`，version 2。四页共用这一份内容源；旧的 profile/projects/experience/home/songs/memories/gallery/littleThings 内容 JS 已合并。全局导航/品牌/页脚仍在 site.js，背景壁纸配置仍在 appearance.js。
- 图片：`public/content/uploads/<随机 ID>.webp` 等。Vite 会复制到 `dist/content/uploads/`，匹配当前 `/` base。
- 上一版本备份：`.editor-backups/<时间戳-ID>.json`，不进入 Git 或网站构建。每次成功保存前生成。
- 保存使用文件指纹校验和串行队列；如果多个窗口或其他程序改动了文件，拒绝覆盖，提示冲突。写入临时文件后原子替换，避免留下半份 JSON。
- 保存失败时当前草稿不清空。先“导出草稿”，刷新加载最新项目后，通过“导入草稿”载入导出文件，再预览、保存；导入也能撤销。恢复旧备份也可通过导入对应 JSON 完成。不要未经核对覆盖另一个窗口的新内容。
- 关闭/刷新有未保存修改的工作台时，浏览器会提示离开。撤销重做保留最多 60 步，连续输入合并；它不跨页面刷新保存。开发者更改编辑器源码触发热重载也可能重置未保存草稿，修改代码前先保存/导出。
- 图片上传会立即保存文件；页面引用仍须点击保存。草稿导出仅含 JSON，不包含图片文件；迁移到另一台电脑需要一并复制图片目录。
- 旧 version 1 草稿/备份仍可导入：只恢复 My World，保留当前首页、音乐、小角落内容。全站 version 2 草稿恢复四页。服务拒绝旧客户端直接写回 v1 文件，避免无意删掉三页数据。

## 结构

```text
src/data/content.json            version 2 → pages.home/world/music/little → blocks[]
src/content/pages.js             页面入口、可用模块与分页面字段定位
src/content/selectors.js         首页屏幕和可播放歌曲的展示适配
src/content/model.js            模块工厂、字段更新、结构验证和链接规则
src/content/store.js            正式页面/编辑预览共享的响应式内容
src/content/richText.js          渲染前富文本白名单
src/components/content/         ContentBlock、ContentText、复用 ProjectEntry
src/editor/                     仅 DEV 加载的三栏工作台、属性表单和预览桥接
server/contentEditor.js         仅 Vite 开发服务启用的本机文件 API
tests/contentEditor.test.js     保存、冲突、上传、权限、结构、历史测试
```

每个模块包含稳定的 `id`、`type`、编辑器名称 `label`、页内导航 `navLabel`、`hidden`、`layout` 和对应 `data`。`layout` 限制为预设布局、对齐、60–100% 宽度、0–160px 上下留白及图片显示参数，不支持任意 CSS。正文保存有限的 HTML 格式；链接与图片资源独立字段。新增模块类型时同步工厂、验证、表单、公共渲染和响应式规则。

## 本地边界与发布

`npm run dev` 仅绑定回环地址，编辑器插件拒绝监听全部网卡。写入 API 同时检查客户端地址、Host、Origin、自定义头及随机会话令牌。只处理固定 JSON 文件和生成的图片路径，不提供任意文件读写。不要用公网隧道或反向代理公开开发服务。服务重启令牌作废，需要重新打开工作台。

`/__editor` 不是生产路由。`import.meta.env.DEV` 分支及 Vite serve 插件使工作台/预览桥接和写入 API 不进入发布构建。正式网站不展示编辑入口，不使用登录安全的假象代替本地隔离。

现有 `peanora.cn`、`base: /`、History 路由、三个目录入口、404.html 和 Actions 不变。提交 JSON、上传资源和对应代码，再按现有工作流构建发布即可；备份、临时文件和 node_modules 不提交。用户最初要求仅本地开发，2026-10-15 后续明确“当前先推送”，现按最新确认推送 main。编辑器及写入接口依然不会发布到网站。

## 以后怎样推送

编辑器里的“保存到项目”完成后，在项目文件夹另开一个 PowerShell 窗口（不必关闭正在运行的开发服务）。先进入目录：

```powershell
Set-Location "E:\Peanora's Space"
git status
npm test
npm run build
```

检查显示的修改属于本次更新，且测试、构建成功，再依次执行：

```powershell
git add .
git commit -m "更新个人介绍和项目内容"
git push origin main
```

提交说明改成这次修改的内容即可。`git add .` 收集当前修改（包含新增图片）；`git commit` 在本地保存一个版本；`git push` 上传到 GitHub。已配置的忽略规则会排除依赖、构建目录、本地备份和环境配置文件。若显示没有可提交的修改，先确认已经在编辑器点击保存。

推送成功后打开 [仓库 Actions](https://github.com/Peanora/peanoras-space/actions)，找到最新的 “Deploy website to GitHub Pages”；显示绿色成功后，再访问 [正式网站](https://peanora.cn/)。上传成功与部署完成是两个步骤。正式访客使用 `peanora.cn`；本地编辑器地址只在运行开发服务的电脑上可用。

若也在 GitHub 网页或另一台电脑改过内容，开始本次编辑前先运行 `git pull --ff-only` 同步。遇到推送被拒绝或红色报错时保留提示，不使用强制推送；可把报错发给我处理。
